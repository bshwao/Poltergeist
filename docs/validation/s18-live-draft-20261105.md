# S18 live request preparation — November 5

No live OpenAI request has been sent. Current local settings disable the
integration and have no project API key or selected model. Those missing inputs
are not replaced with a Codex session or other application's credentials.

A local draft is retained at
`validation-evidence/s10-s19-20261105/s18-live-disclosure-draft.json`.
It selects one actual braking observation from the completed native trained-model
comparison, with its original value, coverage and exact frame/time references.
The disclosed coverage context remains explicit. The proposed question asks
which observation establishes measured braking and what coverage limits apply;
it forbids inferred model reasoning or causation. Raw telemetry, images, model
configuration/weights, filesystem paths, run IDs and unselected observations are
excluded from the proposed outgoing evidence.

The proposed budget is **one provider call**, at most **16,384 bytes** of complete
request JSON and **512 output tokens**, with `store: false` and no automatic
retry. This is a proposal, not user-approved expenditure. A chosen available
Responses model and privately configured project key are required before the
application can generate its real digest-bound preview. The complete preview,
including model, instructions and tool schemas, must fit the byte limit and be
reviewed and approved before sending.

Official [token-counting guidance](https://developers.openai.com/api/docs/guides/token-counting)
confirms that output limits include generated non-visible tokens. The
[Responses migration guide](https://developers.openai.com/api/docs/guides/migrate-to-responses)
documents `store: false` for disabling response storage. This flag is not a claim
about every provider data-retention policy. A price estimate still needs the
actual selected model and its current official rates; no dollar cap or account
access is invented here.

Actual account compatibility, returned usage, bounded tool response, evidence
presentation and the human review remain unverified until that authorized live
call completes. The draft does not satisfy the S18 live-call requirement.

For this isolated acceptance API, a private configuration template is prepared at
`validation-evidence/s10-s19-20261105/providers.private.env.example`. Copy/edit it
locally as `providers.private.env` in the same ignored directory. It defaults to
disabled providers with empty secrets. The acceptance launcher supports
`--check-config`, which reports only public model/repository/App identifiers and
configured booleans. It ignores this optional file when absent and keeps both
providers disabled. Private configuration does not itself authorize a send; the
actual model-bound preview and reviewed budget still precede a live request.
