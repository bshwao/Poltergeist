# S4–S5 local validation on November 2, 2026

This pass builds on the S1–S3 local acceptance at `fe226ef`. S4’s private
account and device workflow and S5’s website workflow were exercised on the
owner’s PC. The S5 completion criterion also requires the deployed public
HTTPS website, its Python coordinator and a successful run through that origin.

## Changes

- Validate ASCII account names before case normalization so Unicode lookalikes
  cannot alias an ASCII account. ASCII case-insensitive sign-in is preserved.
- The dashboard pairing panel displays the exact coordinator origin to enter
  in Companion and explains how to open the app from the Start menu. A hosting
  operator can supply an HTTPS installer link at build time.
- The same-origin coordinator deployment uses a separate single-worker image
  with the hosted site, direct TLS and a persistent SQLite volume. The hosted
  root redirects to `/app/`. The trusted local simulation API is absent from
  the coordinator deployment. See the [deployment runbook](../hosted-dashboard.md).
- The opt-in live browser fixture checks for the CARLA client before starting.
