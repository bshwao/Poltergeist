# S8 recording and review on this PC

The acceptance run used the hosted dashboard over loopback HTTPS/WSS, an
isolated Companion profile, and CARLA 0.9.16 on `Town10HD_Opt` with Low graphics.
The test PC has an Intel Core i7-10750H, an NVIDIA GeForce RTX 2060, and 64 GiB
of RAM. The 120-second experiment exercises the current hosted duration limit.

The first run exposed a display issue after explicit removal. The picker
selected an available recording by default. When every recording was
unavailable, it left the selection blank and hid the reason until someone
selected the item. The picker now selects the first item in that case and
shows its removal or unavailability status immediately.

The full repeat passed. Run `2132987e-acd8-41f6-a8cb-0c08f0d57556` recorded
2,401 frames and 4,802 camera and LiDAR samples, totaling 606,061,328 raw
bytes. Chromium traversed all 193 metadata pages and verified early camera,
early LiDAR and late-frame previews. It requested no evidence during execution.
Successful evidence responses totaled 3,607,258 bytes. Metadata response p95
was 57 ms over loopback. The coordinator enforced the existing account limit
once, and the test honored its 32-second retry interval before continuing.
Retained JavaScript heap after explicit collection rose from 4,057,664 to
5,306,172 bytes.

The exported ZIP was 621,423,108 bytes. The archive verifier checked all
4,802 sample hashes and ZIP integrity. Removing the test run's evidence
reclaimed 620,057,503 bytes in the Companion profile. The dashboard showed
explicit removal and kept the original completed summary visible. All 397
frontend tests passed. A CARLA RPC retry confirmed that the world had returned
to asynchronous mode with no dynamic actors before the test instance stopped.

A separate real CARLA run used a 1 MiB quota on a disposable profile. Capture
stopped with an explicit storage limit error and published no partial recording.
Only 14,596 bytes of result artifacts remained from the failed run, including
its measured telemetry. The next uncaptured CARLA run completed with five
frames. The existing focused suites passed 15 Python checks and six browser
client checks covering quota and reserve handling, version and hash validation,
transfer cancellation, and missing and deleted evidence.

The browser test uses the normal coordinator transfer limits and the
Companion's normal evidence export and removal methods. The retention check
operates on the single completed run in its disposable fixture profile.
